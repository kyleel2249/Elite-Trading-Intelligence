# Repository audit: 8 November 2026

Baseline: `main` at `5da2e1442477b1a9fa90d33d7352ca6a025ce622`. Repairs are proposed on `fix/repository-audit`, not deployed or merged.

## Assessment

The baseline passed 66 tests but contained security and execution-accounting defects. This repair set passes 209 Python tests and 14 JavaScript tests locally, plus Python compilation and `git diff --check`. Provider calls in safety tests are mocked. These results do not certify production or live-trading readiness.

## Repairs

- Reject Alpaca testnet and endpoint/environment mismatches before broker submission, including attempts to reach a live endpoint under a paper label.
- Require finite positive server reference prices and size orders against a conservative full-notional budget. `default_risk_per_trade_pct` now limits full order notional as a percentage of equity until enforceable stops exist; it is not a calibrated maximum-loss estimate.
- Pass server quotes from both order and strategy callers; a client limit price cannot substitute for a missing market quote.
- Book confirmed cumulative broker executions, including partial fills and partial-then-canceled orders, rather than treating quote hints or submitted status as fills. Derive Binance market fill prices from executed and cumulative quote quantities.
- Prevent same-order execution replays from duplicating holdings, retain submission intent before external calls, and preserve ambiguous submissions for reconciliation. Recalculate unrealized PnL immediately after position changes.
- Send price/time-in-force for Binance limits; simulated limits only cross at a supplied market price.
- Protect forecast scoring and private account reads with API-key authentication. Validate prices and bound query sizes. GET persistence is now off by default; explicit persistence requires authentication.
- Pin the Cloudflare proxy to its configured origin, reject unsafe backend URLs, and avoid leaking backend configuration in error messages.
- Escape external dashboard values and attribute JSON. Remove legacy persistent API keys and use tab-session storage instead.
- Default settings to production, validate environment names and job intervals, and bind Compose to loopback. Explicitly configure an API key before using protected routes.
- Fix background-job cancellation and lifespan cleanup.
- Correct backtest signal timing, allocation, fees, mark-to-market drawdown, terminal liquidation and closed-trade win rates. Walk-forward training bars only warm signals; test-fold returns compound.
- Reject non-finite market prices and corrupt forecast history; correctly convert timezone-aware quote timestamps. Test settings override inherited live flags.
- Add Python and JavaScript security regressions to CI.

## Remaining work before live use

1. Implement stable request idempotency and transactional portfolio-wide reservations. Same-order execution replays are protected, but different concurrent orders across processes can still race. A retried HTTP order currently receives a new client-order ID. Never automatically retry `submission_unknown` as a new order; reconcile its existing client-order ID first.
2. Add broker exchange tick/step/min-notional filters, commission accounting, and actual broker-account/equity synchronization. Full-notional sizing is deliberately restrictive but does not replace portfolio/correlated-exposure controls or enforceable stop orders.
3. Replace shared-key authorization with scoped user/account permissions where multiple users share a deployment. Session storage is still accessible to same-origin JavaScript; escaping is not a complete security boundary.
4. Review and repair historical positions/PnL separately. Code fixes do not undo incorrect historical accounting. Execution state currently uses namespaced JSON in order notes rather than a dedicated execution ledger/migration.
5. Validate a Docker build, migrations on the intended database, browser end-to-end behavior, actual Cloudflare deployment and broker sandbox behavior. None of these was exercised in this run. Dependencies are still broadly ranged; no independent dependency-vulnerability audit was completed.
6. Improve forecast validation: scoring remains an authenticated manual/current-price comparison, not horizon-matched model calibration. Backtests remain close-only educational simulations without slippage, stops, or parameter optimization. Noncrossing simulated limit orders have no background matching engine.

Keep live trading disabled while this work remains. No real order, production change, deployment, or historical data repair was performed.

## Compatibility notes

Private dashboard reads now need the API key. Default analysis GETs no longer save forecasts or council decisions: request `persist=true` with authentication when storage is wanted. Docker's port is intentionally local-only; external access requires an explicitly configured proxy or tunnel. Unknown environment names fail settings validation. Orders that previously passed because risk was assumed rather than measured may now be rejected.
